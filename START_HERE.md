# Start here

1. Read README.md and PROJECT_RULES.md.
2. Inspect the adopting project's actual architecture and approved scope.
3. Use the relevant engineering role, playbook and optional profile.
4. Treat Draft documents/policies as unanswered questions, not decisions.
5. Run local documentation/tests and record evidence before committing.

The reusable project graph is in docs/README.md. Polaris adoption, design identity and security evidence are explicit project decisions, not compulsory package dependencies.
